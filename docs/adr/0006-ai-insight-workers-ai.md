# 0006. AI 结果解读：Workers AI + 分桶缓存 + 静态降级

- 状态：已接受（2026-08）

## 背景

结果页希望引入 LLM 生成的个性化解读（「AI 时代」的核心体验升级），但面临四条硬约束：仓库不携带任何 API 密钥；免费额度（Workers AI 每日 10000 Neurons）有限；项目隐私承诺是「逐题答案不出浏览器」；AI 输出不能破坏自有角色文案的一致性（不能幻觉出资料之外的作品与人名）。

## 候选方案

1. **调用 OpenAI/Anthropic 等外部 API**：质量最好，但需要密钥管理、按量付费、数据出境第三方，四条约束全部违反。
2. **浏览器端小模型（WebLLM/WebGPU）**：零服务器成本，但 1B+ 模型首载 0.5GB 起步，移动端不可用，与 4MB 级 JS 预算冲突。
3. **Cloudflare Workers AI binding + D1 分桶缓存**：与 D1 同套部署体系，`wrangler.jsonc` 声明 binding 即用、无密钥；配合缓存把消耗压到常数级。
4. **对话式 AI 访谈替代固定题库**：体验前沿，但会摧毁固定题库的信效度基础与可复现性，且 token 成本高出两个数量级。

## 决定

采用方案 3，并确立三条设计红线：

1. **隐私**：请求只含角色代码、四维倾向分（[-1,1]）与语言，绝不接收逐题答案；提示词素材来自构建期生成的角色精简档案（`functions/api/_data/characterBrief.json`，随 `npm run generate:data` 自动同步）。
2. **成本**：以「角色 + 四维倾向分桶（强/中/轻微 → 3⁴=81 桶）+ 语言」为缓存键写入 `ai_insight_cache`（迁移 0009）。相同画像全站共享一次生成结果，消耗与画像桶数同阶（≤ 113×81×4）而非与流量同阶；「换一种说法」走 `fresh: true` 重新生成并覆盖缓存，前端限 3 次/结果。
3. **降级**：未绑定 AI、额度耗尽、生成失败一律返回 `{available:false}`，前端隐藏整卡，结果页静态解析文案完全不受影响。

一致性控制：模型 `@cf/meta/llama-3.2-3b-instruct`、温度 0.2；提示词明确「只依据给定资料改写、禁止引入档案外的作品名/人名、角色名最多出现一次」；输出经去引号/截断清洗后落缓存。

补充（2026-08-22）：**模型调用增加 REST 直连回退**（`runModel`）。起因是本地 `pages dev` 的 AI binding 依赖 wrangler 远程代理会话（`<hash>.<账号>.workers.dev`），在受限网络下该域名既有 DNS 投毒又有 SNI 阻断，远程绑定 RPC 确定性 `internal error`（而同账号 REST 调用经代理完全正常）。REST 凭据从 `.dev.vars` 的 `ACGTI_AI_TOKEN`/`ACGTI_AI_ACCOUNT_ID` 读取，由 `npm run dev:pages` 自动注入（复用 wrangler OAuth 登录态）。线上仍以 AI binding 为第一优先（零配置零凭据），REST 仅作本地与特殊环境的联调通道——这也是「渐进增强」原则在开发工作流上的延伸。

## 后果

- 正面：部署即用、零密钥、零边际成本（缓存命中后）；隐私模型不变；降级路径保证功能永不因 AI 不可用而破损。
- 负面：3B 模型的多语言质量有上限（日语输出偶发不稳）；缓存文案全站同画像共享，个性化粒度是「分桶级」而非「个人级」——这是有意的取舍，用免费额度换确定性。
- 演进方向：模型升级只需改常量并清空缓存表（缓存行记录 model 字段）；若未来引入付费档位，可在同端点上放开分桶精度与流式输出。
