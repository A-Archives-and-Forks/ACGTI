# 0004. 匿名统计：聚合表自增 + 低比例抽样明细，不做用户系统

- 状态：已接受（2026-04）

## 背景

统计页需要展示全站分布（角色命中排行、原型分布、总量趋势），校准流水线需要按题明细。产品定位是娱乐向心理测试，不应该也没有必要收集身份信息；且本项目无登录、无鉴权、无邮件系统。

## 候选方案

1. **全量明细入库**：分析最灵活，但流量增长后存储与隐私面都不可控，且 D1 写入吞吐有上限。
2. **纯第三方统计**：省事，但自定义维度（角色/原型）统计难做，数据不归仓库所有。
3. **聚合表 UPSERT 自增 + 2% 抽样明细**：每次提交只对四张聚合表（archetype/character/pair/daily）做原子自增；2% 的提交按概率保留完整答案明细（`submissions_sampled` + `submission_answers_blob`）供校准；主动反馈（用户自报真实 MBTI）单独走 `mbti_feedback` 表，是校准的主要数据源。

## 决定

采用方案 3。为保护不可逆的聚合计数，上报入口做分钟级 IP 限流（D1 原子 UPSERT 计数）；为防枚举探测，非法输入与成功同样返回 204 空体。所有上报字段经白名单提取与范围校验（如答案统一为五档 ±2 量程），无任何可识别个人的字段——`submissionId` 是本地生成的随机 UUID，仅用于去重。

## 后果

- 正面：存储量为常数级（聚合行数固定）+ 低速增长的抽样表；统计查询读聚合表即可，无需扫明细；隐私声明可以写得很硬。
- 负面：聚合表无法事后纠错（脏数据只能靠入口限流与校验预防）；2% 抽样意味着小流量时期明细样本稀疏，需靠主动反馈补足。
- 数据回流：cron-worker 每 15 分钟把聚合表重算为快照（`stats_snapshot`），统计端点只读快照，读写路径彻底分离。
