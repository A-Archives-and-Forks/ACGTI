# 0001. 前后端一体托管于 Cloudflare Pages + D1

- 状态：已接受（2026-04）

## 背景

ACGTI 的产品形态是「一次测试 + 匿名统计 + 结果分享」，需要极致低的运维成本与全球可达的访问速度，同时项目无商业化预算。核心计算（MBTI 计分、角色匹配）必须留在浏览器本地以规避隐私顾虑，后端只承担统计收集。

## 候选方案

1. **静态托管 + 第三方统计 SaaS**（Vercel + Google Analytics 类）：零后端，但数据不属于自己、定制统计（角色分布/原型排行）难做，且引入隐私合规负担。
2. **传统小服务器**（VPS + Node/Python + SQLite）：自由度高，但要自己管证书、进程、备份、全球加速。
3. **Cloudflare Pages + Pages Functions + D1**：前端静态资产与后端函数同仓库同域名部署，D1 是托管 SQLite，免费额度覆盖项目量级，天然免运维。

## 决定

采用方案 3。前端 Vue 3 + Vite 构建产物直接由 Pages 托管；`functions/api/*` 提供 6 类端点（上报、反馈、AI 解读、统计查询、配置、健康检查）；D1 承担聚合计数与缓存。统计快照的定时重算由独立的 cron-worker（每 15 分钟）完成，避免把定时逻辑塞进请求路径。

## 后果

- 正面：部署 = git push 后 Pages 自动构建；无服务器要维护；边缘节点全球加速；D1 免费额度内零成本。
- 负面：Functions 是非 Node 运行时（workerd），部分 npm 包不可用；D1 单点写入吞吐有上限（本项目量级远未触及）；深度绑定 Cloudflare 生态，迁移需要重写 functions 层（前端与数据层可平移）。
- 缓解：functions 层刻意保持极薄（输入校验 + SQL），业务逻辑全部在前端或 analysis 流水线，锁定风险可控。
