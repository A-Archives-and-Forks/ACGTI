# 0002. 纯 SPA 无 SSR，以静态元数据 + 站点地图兜底 SEO

- 状态：已接受（2026-04）

## 背景

站点需要被搜索引擎收录（首页、图鉴页、统计页），但测试结果页本质是个人数据，无服务端渲染的必要。SPA 的核心痛点是首屏 HTML 里没有内容可供爬虫与社交分享卡片抓取。

## 候选方案

1. **Nuxt/SSG 混合渲染**：最完整的 SEO，但引入整套新框架与构建复杂度，与「轻量优先」冲突。
2. **预渲染（vite-plugin-prerender）**：构建期生成静态 HTML，但七条路由内容多为运行时数据（统计、角色库），预渲染收益有限。
3. **纯 SPA + 静态元数据兜底**：`index.html` 写死默认 OG/Twitter 标签与结构化数据；每路由用 `useSeo`（unhead）动态更新标题/描述/canonical；提供 `sitemap.xml` 与 `robots.txt`；分享主载体是**结果海报图片**而非结果页 URL。

## 决定

采用方案 3。OG 图片由脚本 `npm run generate:og` 从真实首页截图生成（1200×630），避免手工维护设计稿；结果页 URL 仅服务于本人回看与角色预览（`?character=`），对外分享一律引导海报图 + 文案（含角色代码与站点链接）。

## 后果

- 正面：构建链保持 Vite 单一；分享转化不依赖爬虫对动态路由的理解；海报在社交平台的视觉表现优于链接卡片。
- 负面：结果页本身不被索引（有意为之——个人数据不应进入索引）；依赖 JS 执行的路由对部分爬虫不可见，新增营销页时需评估是否值得预渲染。
- 补充：页面加载失败场景由 `index.html` 内联的纯 CSS loading 屏兜底，`noscript` 用户看到明确提示。
